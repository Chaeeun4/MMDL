# 박채은 · MMMU 평가 및 도메인 SFT 실험 정리

**결론.** 악보 원본 전사만 학습한 PrIMuS step 500은 초기 60문항 탐색에서 24→29/60이었지만, 같은 조건의 통제 평가에서 30→26/60으로 바뀌었다. seed 5개에서 1승 1무 3패였고, 900문항에서는 **576→577/900**이었다. 이 실험으로 PrIMuS 단독 SFT가 일반 멀티모달 성능을 개선했다고 판단하기 어렵다.

## 1. 실험별 목적과 관찰

| 실험 | 확인하려던 것 | 관찰 |
|---|---|---|
| Base 평가·재채점 | 생성 조건과 답 추출이 기준 점수에 미치는 영향 | 원래 평가 580/900. 기존 재채점 583/900, 이후 공통 재채점 582/900. 두 재채점은 각각의 파서와 결과 파일을 함께 기록한다. |
| PrIMuS raw 단독 SFT | 원본 악보 전사 학습이 음악과 전체 정확도를 올리는가 | 초기 최고 29/60. 900문항 통제 비교에서 음악 10→6/30, 전체 +1/900. |
| PubChem 단독 SFT | 분자 구조·좌표 과제가 화학으로 전이되는가 | 저장 평가에서 화학 14/30, 전체 555/900. 공통 재채점 558/900. 오래된 Base와 생성 설정이 달라 직접 효과는 미확정이다. |
| PrIMuS + PubChem SFT | 두 원본 과제를 함께 사용할 때 일반 성능이 개선되는가 | 저장 평가 547/900. 공통 재채점 550/900. |
| 동일 설정 비교 | 초기 개선을 seed·컨텍스트·평가 범위에 걸쳐 재현할 수 있는가 | Base/PrIMuS 60문항 쌍 5개와 900문항 쌍 1개를 확보했다. 16K→32K에서는 일부 길이 종료가 줄었지만 Base 점수는 30/60으로 같았다. |
| MMMU-Pro Standard | 공식 설정에서 팀 Base·offc1b와 PrIMuS를 비교할 수 있는가 | PrIMuS step 500의 **official 1,730문항** 실행을 원격에서 시작했다. 최종 결과는 아직 이 브랜치에서 확인하지 못했다. |

학습 설정은 [SFT YAML과 학습 기록](../sft_train_artifacts)을 참고한다. 세 기존 SFT 설정은 Qwen3-VL-4B-Instruct, LoRA rank 16·alpha 32, 학습률 1e−4, 2 epoch, cutoff 2,048을 사용했다. **학습 cutoff와 평가 출력 한도는 별개**다. PrIMuS·PubChem 단독과 혼합 실험은 각각 [PrIMuS 설정](../sft_train_artifacts/configs/sft_primus_only.yaml), [PubChem 설정](../sft_train_artifacts/configs/sft_pubchem_only.yaml), [혼합 설정](../sft_train_artifacts/configs/sft_both.yaml)에 있다.

## 4. 실패 사례와 다음 데이터의 근거

- **Electronics_30 · 연결 판독.** 두 모델 모두 가지가 있는 RC 회로를 직렬처럼 합쳐 같은 위상 오답을 냈다. 보강하려는 것은 소자 이름 암기보다 **각 소자가 어느 노드에 연결됐는지** 읽는 능력이다.
- **Math_5 · 그래프 조건 적용.** 두 모델 모두 x축의 (2,0)을 두 곡선의 교점으로 사용했다. 연산 규칙을 알더라도 필요한 경계를 잘못 읽으면 적분 구간이 바뀐다.
- **Chemistry_11 · 채점 점검.** Base가 공식 기록상 오답이었지만, 그 풀이의 산·염기 투입 방향이 상승하는 pH 곡선과 맞아 보인다. 공식 점수는 유지하고 정답표·선택지 재검토 사례로 둔다.
- **Music_22 · 점수와 풀이.** PrIMuS는 정답으로 채점됐지만 화음의 여러 음을 단음처럼 설명했고 길이 종료됐다. 맞힌 답과 근거가 타당한 답을 구분한다.

900문항 중 두 모델의 공통 오답은 **251개**, 한쪽만 맞힌 문항은 **145개**다. 그중 **46개**에서 풀이를 직접 대조했고 음악 오답 관련 27개를 전부 포함했다. 나머지 350개의 오류 원인은 미판정이다. [기존 음악·화학 오답 분석](sft_analysis/mmmu_error_analysis.md)

## 5. 후속 진단 및 중복검사

- **전수 중복검사 완료.** AI2D 15,501 + ECD 321,544 + ViRL 38,870 = **375,915문항**. **11,470문항(3.05%)**이 자동 후보로 표시됐다. 정규화 문자열·8-gram·MMMU-Pro Vision OCR과 이미지 SHA-256·pHash·SigLIP 임베딩을 사용했다. 후보가 있는 AI2D·ECD 이미지 그룹 전체를 제외하는 방식으로 선별할 계획이며, 그룹 적용 후 정확한 잔여 수는 여기서 확인하지 못했다.
- **프롬프트 진단 준비.** 비벤치마크 AI2D 5문항과 ECD 5문항에 검증 전사를 만들었다. 같은 Base에서 원본 이미지·Qwen 전사·검증 전사를 비교하는 파일럿이다. 진단용 이미지 그룹은 학습에서도 제외한다. 완료된 진단 점수는 확인하지 못했다.
- **후속 SFT 계획.** 일반 ViRL 대조군과, 같은 예산 내 일부를 AI2D 연결 QA 또는 ECD 조건·계산 QA로 교체한 모델을 비교한다. 4,000개 기준 공통 ViRL 3,000개와 보강 1,000개가 목표다. 이 규모는 설계안이며 학습 결과가 아니다. [실험 계획과 중복검사 방법](../experiments/targeted_sft/README.md)
- **MMMU-Pro 비교 조건.** PrIMuS는 jina 계열의 official 지시문과 생성 설정으로 Standard test를 평가 중이라는 원격 로그를 확인했다. 종료 지표가 확보되면 동일 split·리비전·설정 여부와 생성 오류 수를 확인하고 별도 결과 행을 추가한다. 이전 자체 Base pro_cot 실행은 32개 이미지 참조 제한 오류로 중단됐으므로 완주 점수는 없다.
